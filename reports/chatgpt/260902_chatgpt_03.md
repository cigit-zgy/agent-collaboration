Install the three approved machine-wide verification utilities—Semgrep Community Edition, CodeQL CLI, and `pip-audit`—using the smallest conventional macOS setup, verify that each executable is usable, and record the resulting machine state without running repository scans or mutating any project environment.

This is a light machine-setup task. Speed and scope control are requirements.

## Required changes

### A. Initial repository synchronization

Follow `references/protocol.md`:

```text
git fetch
→ inspect branch / HEAD / upstream / git status --short
→ preserve pre-existing user changes
→ safe fast-forward only if merely behind
→ no invented merge/rebase/reset/stash/force-push
```

If the repository is divergent or contains conflicting user changes, do not destroy or hide them.

### B. Pre-install inspection

Run the minimum checks needed to establish current machine state:

```text
brew --version
command -v semgrep || true
command -v codeql || true
command -v pip-audit || true
```

If an executable already exists, inspect its version and installation source. Do not reinstall or replace a healthy existing installation merely for consistency.

### C. Install missing tools

When Homebrew is available, install only missing tools:

```text
brew install semgrep
brew install --cask codeql
brew install pip-audit
```

Do not run `brew upgrade`, `brew update` solely for freshness, or reinstall unrelated packages unless Homebrew itself requires a minimal metadata refresh as part of normal installation.

Do not install any of these tools into:

- a project Conda environment;
- a project `.venv`;
- `water-bioprocess-agent`;
- any first-party Skill runtime.

Do not add them to project `pyproject.toml`, requirements, lock files, or Skill inventories. They are machine-wide developer utilities, not Skills or project dependencies.

If Homebrew is unavailable or an approved package cannot be installed safely, report the concrete blocker rather than inventing a new package-management system.

### D. Post-install verification

Verify only basic executable readiness:

```text
semgrep --version
codeql version
pip-audit --version
```

For CodeQL, additionally run a lightweight non-project readiness command such as:

```text
codeql resolve languages
```

Do not create a CodeQL database and do not scan any repository in this task.

For Semgrep, do not run `--config=auto` scans in this task.

For `pip-audit`, do not audit any project environment in this task.

Record executable path and version for all three tools in the Codex report.

Do not add these tools to `/Users/wenv/Documents/skills/LOCAL_SKILLS.md`; they are not Skills.

Only change those files if the active content is factually inconsistent with the already committed policies, and explain any such exception.
