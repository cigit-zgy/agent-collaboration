# Repository-native continuity for multi-conversation projects

## Context / problem

Long-running research/software projects routinely span many ChatGPT conversations. The previous handoff model still encouraged each retiring conversation to summarize substantial project state before the next conversation started. Even when the summary was pointer-first, a new conversation could load:

```text
project AGENTS
+ collaboration recovery rules
+ handoff
+ design index/topics
+ active task/report
+ historical rationale
```

before useful work began. In high-intensity projects this duplicated information already durable in the repository and caused new conversations to consume significant context shortly after creation.

The User accepted a stronger separation between repository memory and conversation working memory.

Relevant principle: repository knowledge should be the system of record; Agent entry instructions should act as a map rather than a large manual; progressive disclosure should load deeper context only when the current concern requires it.

Relevant principle: fresh contexts can continue long-running work effectively when durable progress/state artifacts and repository history let the next session recover the current edge without reconstructing the entire previous context.

## Accepted model

The project repository is the durable memory. A conversation is disposable working memory.

```text
AGENTS.md
= project constitution / authority map

design/
= what we currently accept / current design state

CURRENT.md
= what we are working on now / mutable current work pointer

reports/concept/
= how we thought / historical design reasoning

reports/chatgpt/ + reports/codex/
= durable task specification / execution evidence

Git history
= repository evolution

reports/handoff/
= exceptional conversation-only delta only

ChatGPT conversation
= temporary working memory that may be discarded when full
```

## CURRENT.md decision

A maintained long-running or multi-conversation project should use exactly one repository-root:

```text
CURRENT.md
```

It contains only the present work edge and direct pointers needed to resume it. It is mutable current state, not a log.

Typical information:

```text
status / updated timestamp
current work edge
active branch/task/report coordinates when relevant
directly relevant current design/Skill owners
at most a few unresolved blockers/decisions
one next action
```

It must not accumulate chronology, old task summaries, test-result history, architecture copies, design semantics, or rejected alternatives.

Target size is normally <= 4 KiB. Above ~8 KiB is a design/routing smell requiring review rather than further accumulation.

## Normal conversation switch

Routine conversation replacement is **conversation resume**, not **project migration** and not automatically a **handoff**.

Before retiring an old conversation:

```text
accepted design delta        → design/
valuable design reasoning    → reports/concept/ when useful
task specification/evidence  → existing reports/chatgpt or reports/codex owner
current work edge             → overwrite CURRENT.md
residual conversation-only information with no proper owner
                             → exceptional tiny handoff only when genuinely necessary
```

No project-wide summary is produced merely because the conversation is full.

## New-conversation bootstrap

A mature project normally resumes with:

```text
AGENTS.md
→ CURRENT.md
→ design/README.md
```

This is orientation only. After the current concern is identified, load just-in-time:

```text
one directly relevant design topic
+ project Skill/reference only when execution requires it
+ exact active task/report only when the current edge points to it
+ exact concept note only when historical rationale is actually needed
```

Do not preload the complete design tree, reports/concept, old tasks/reports, old handoffs, or collaboration reference tree.

Before the first substantive repository-changing write, resolve current collaboration authority once according to the existing collaboration refresh rule; that does not justify preloading unrelated collaboration owners during orientation.

## Handoff demotion

`reports/handoff/` is no longer the normal project resume mechanism.

Create a handoff only when meaningful conversation-only continuity would otherwise be lost and cannot reasonably be made durable in AGENTS/design/CURRENT/task/report/concept or another real repository owner.

A conforming handoff is a tiny delta capsule, not a project summary. Normal target is <= 4 KiB; > 8 KiB requires explicit review for duplicated repository-native material.

No handoff is preferable to a redundant handoff.

## Startup-context discipline

The normal bootstrap supplied by the User should be a short locator, ideally <= 1 KiB, for example:

```text
continue <repository>
this is conversation resume, not project migration
recover from AGENTS.md → CURRENT.md → design/README.md
load only the current concern just in time
```

The first assistant response after recovery should also stay compact. Do not reconstruct and reprint the entire project merely to prove recovery.

The initial project-text read set should normally remain approximately within 10–12 KiB before the current concern is identified. Exceeding ~16 KiB before useful work begins is a routing smell, not an invitation to expand the handoff.

These are architecture signals rather than parser quotas; a real project may justify an exception, but the default is aggressively pointer-first.

## Sequential versus concurrent conversations

This design optimizes the common case of sequential replacement of a full conversation.

Do not introduce per-conversation state files or a `work/` registry preemptively. If a project later has genuinely concurrent, long-lived work streams whose mutable states interfere, design that concurrency explicitly rather than turning CURRENT.md into a historical/session database.

## Design consequence

```text
NEW_OWNER references/project/current.md
UPDATE   references/project/handoff.md
UPDATE   references/project/architecture.md
UPDATE   references/project/migration.md
UPDATE   references/project/reports.md
UPDATE   project templates / SKILL / AGENTS / README routing
```

The durable invariant is:

```text
repository carries continuity
conversation carries working memory
CURRENT.md carries only NOW
handoff carries only exceptional residual delta
```
