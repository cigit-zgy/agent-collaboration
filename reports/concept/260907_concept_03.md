# Bind Codex repository tasks to a remote synchronization handshake

## Context / problem

ChatGPT authors and publishes task specifications and repository changes through GitHub, while Codex executes on the User machine. A stale local checkout can therefore make Codex operate on a repository state different from the state ChatGPT actually reviewed and issued.

The existing execution contract already required `fetch` before local work and `push` followed by upstream verification when practical. That wording was directionally correct but not strong enough: post-push equality could be skipped, and the pre-execution relationship between the fetched remote state and the exact authorized task baseline was not explicit enough.

## Accepted design

Every repository-changing Codex task, `LOCAL-QUICK` or `FORMAL`, uses a mandatory two-sided synchronization handshake.

```text
PRE-EXECUTION
fresh remote fetch
→ inspect repository / branch / HEAD / upstream / worktrees
→ resolve the exact authorized remote task/baseline state
→ establish a safe local execution checkout/worktree
→ prove local execution HEAD == authorized remote baseline
→ only then mutate repository state

POST-EXECUTION
commit task-scoped changes
→ push owning branch
→ fresh remote fetch again
→ prove local task HEAD == fetched upstream task-branch HEAD
→ only then report repository-changing task completion
```

The contract is about **latest authorized remote state**, not blind `git pull` of the primary checkout. `git pull`, reset, rebase, stash, force checkout, or other history/worktree mutation is never required merely to synchronize and may be unsafe in the presence of User state.

Use fetch plus a safe task branch/worktree or another explicitly authorized local arrangement.

## Failure behavior

If the fresh fetched remote branch does not match the task coordinate/baseline expected by the committed task, or if the post-push fresh fetch does not show local HEAD equal to upstream HEAD:

```text
STOP
→ preserve User/local state
→ report BLOCKED/FAIL as appropriate
→ do not claim PASS
```

Do not silently execute from a stale local checkout, silently adopt an unexpected newer remote branch head, or claim upload success based only on the push command's exit status.

## Scope

This handshake is mandatory for repository-changing Codex work. A read-only/local-only task that intentionally does not change the repository does not need a push step, but it still resolves current remote/project authority when repository state materially affects the result.

## Operational consequence

Current operational ownership remains in `references/collaboration/execution.md`. LOCAL-QUICK and FORMAL task templates explicitly inherit the handshake, and FORMAL reports record the final upstream-equality evidence.
