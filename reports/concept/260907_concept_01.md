# Separate concept journal from single living design

## Context

The previous project policy used dated files under `reports/concept/` as both design-history records and canonical current design authority. For complex research projects this mixes two different needs:

```text
recover how we thought
versus
read what the project currently accepts
```

The User explicitly accepted separating these responsibilities.

## Accepted direction

```text
reports/concept/
= chronological design journal
= exploratory/incomplete/rejected/superseded reasoning may remain
= not current authority

design/
= current accepted structured design
= one current set only
= no history/old/draft/versioned alternatives inside
```

## Dynamic design structure

`design/` is not a fixed universal set of topic files. The topic count is determined by current project responsibilities.

A topic is added/split/merged/removed/reordered when its current responsibility, boundary, interface, consumer, trust semantics, or change lifecycle justifies that restructuring.

File length alone does not justify a split.

Stable semantic identity lives in `design_id`; numeric prefixes express current reading order only.

## Concept reduction

A concept note is an input event rather than a design version. After User + ChatGPT adjudication it may produce:

```text
NO_CHANGE
UPDATE
NEW_TOPIC
SPLIT
MERGE
REMOVE
REORDER
```

Many concept notes may reduce into one design update; one concept note may affect several design files; some notes produce no current-design change.

## Single-current-set invariant

No project may retain competing current design sets such as `design_v2/`, dated design directories, old topic copies, or draft/backup versions under `design/`.

History is recovered from Git plus `reports/concept/`.

## Operational consequence

Current project contracts are split into:

```text
references/project/concept.md
= concept-journal semantics

references/project/design.md
= living-design authority + dynamic decomposition

references/project/templates/concept.md
= concept-note authoring

references/project/templates/design.md
= living-design authoring/restructuring
```

Project AGENTS/Skill/architecture/prior-art/report policy now route current design through `design/`.
