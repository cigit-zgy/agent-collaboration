# Locator-only Codex task delegation

## Problem

Long Codex instructions were still being expanded directly in chat, including LOCAL-QUICK tasks with many filesystem, Git, integrity, and stop constraints. This duplicated task context and consumed conversation tokens.

## Accepted design

Every repository task delegated to Codex first becomes:

```text
reports/chatgpt/YYMMDD_chatgpt_NN.md
```

That committed file is the sole task-specific execution specification.

User-visible delegation is locator-only:

```text
optional one short sentence
+ one fenced text locator
```

Mode distinction:

```text
LOCAL-QUICK
→ committed reports/chatgpt task
→ short locator
→ compact Result contract
→ no reports/codex report

FORMAL
→ committed reports/chatgpt task
→ short locator
→ bound reports/codex report
→ acceptance/integration lifecycle
```

If the task cannot be committed and pushed, ChatGPT reports the repository-write blocker rather than substituting a long chat-only prompt.

If LOCAL-QUICK expands across a FORMAL boundary, Codex stops and reports the escalation reason; a new durable FORMAL task is issued instead of extending the task in chat.

## Design consequence

Incorporated into `execution.md`, `formal.md`, `project/reports.md`, both Codex-task templates, `SKILL.md`, root `AGENTS.md`, and the project AGENTS template.
