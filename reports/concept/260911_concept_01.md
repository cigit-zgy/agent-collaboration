# Context

The User wants a cleaner repository root while keeping the existing two-layer design model:

```text
reports/concept/
= what we considered / historical design thinking

reports/design/
= what we currently accept / one canonical living design set
```

The earlier contract placed `design/` at repository root. That separation was semantically clear but added another top-level project-governance directory.

# Accepted decision

Move the canonical living-design location to:

```text
reports/design/
```

`reports/design/` is **not** a report family. It is a special current-authority directory co-located under `reports/` for project-governance compactness.

Therefore the active governance layout becomes:

```text
reports/
├── design/      current living design authority
├── concept/     chronological design history/input
├── chatgpt/     durable Codex task specifications
├── codex/       FORMAL Codex execution evidence
└── handoff/     exceptional conversation-only delta
```

`CURRENT.md` remains repository-root current work state because it is the low-cost resume pointer, not design/report history.

# Design-directory exception

The report-family rules apply only to:

```text
chatgpt
codex
concept
handoff
```

They do not apply to `reports/design/`.

Specifically, `reports/design/` may and normally should contain:

```text
README.md
00_overview.md when justified
NN_<semantic-topic>.md
```

It is dynamically decomposed by design concern, not chronology. It does not use `YYMMDD_<family>_NN.md`, report metadata, or flat-report semantics.

# Current-state invariants

```text
one project
→ one reports/design/ tree
→ one current accepted design set
→ no old/draft/versioned alternatives inside
```

History remains in Git plus `reports/concept/`.

# Resume consequence

Normal multi-conversation resume becomes:

```text
AGENTS.md
→ CURRENT.md
→ reports/design/README.md
→ just-in-time current owner
```

The User shorthand remains otherwise unchanged.

# Migration consequence

Existing mature projects using repository-root `design/` should move that current tree to `reports/design/` during the next collaboration-architecture normalization. This is a path migration only; it must not rewrite project-specific scientific/product semantics.

# Operational projection

Update current collaboration owners/templates so all current-design references use `reports/design/`, while preserving historical concept files unchanged.
